# Use the bill to make a decision.

mlspend is a portfolio demonstration. Its platform costs are simulated with known truth. Its portfolio costs are shadow estimates of public project usage at published list prices; nobody paid these amounts. No figure is a quote, an invoice or financial advice.

A practical review path for an engineering lead, finance partner or interviewer.

## Review sequence



| Decision | Evidence | Action |
| --- | --- | --- |
| Does the bill reconcile? | Source records and four-grain count/cost reconciliation | Stop if count or currency differs |
| Who owns idle? | Allocation policies and idle-before-allocation table | Agree the policy before chargeback |
| Can this reduce the bill? | Whole-platform counterfactual and capacity externality | Check whether a node can actually be removed |
| Can we commit? | Development optimum and held-out regret | Keep uncertain demand on demand |
| Is the API awake? | Two browser GET health attempts | Use visibly local calculation when unavailable |
| Was it saved? | Returned identifier and independent readback | Never assume a timed-out POST failed |

## Limits and pushback

Review the limitations beside each method. A recommendation is an experiment to validate, not authorization to change an unrelated production system.
